# 0.7 — stable local Codex + GitHub Actions crabbing

Owner-selected goal, 2026-11-16. Planned, not implemented or released. This replaces
historical #536's version split and takes priority over unrelated 0.7 expansion.
Foundations are in [0.6.11](0.6.11-scope.md); execution/data boundaries are in
[design 09](../design/09-actions-local-codex.md).

## Required result

Local Codex takes the receiving goal and pair. Trusted scripts run on Actions,
return bounded evidence and accept bounded follow-up requests. Local Codex judges
nutrients, prepares an own-maw patch or issue, obtains receiving verification on
Actions and performs authorized final issue/PR delivery locally. The prey is never
cloned, archived, cached or materialized as a repository locally, including on failure.

Every nutrient and final issue/PR draft includes clickable permalinks to its exact
source commit, file and relevant lines, with an explanation of what is being taken
or adapted. The user can open the repository and assess the source directly.
Bounded evidence artifacts remain allowed; they do not replace those links.

Only the allowed inert evidence reaches the local model. No local Crab processing
host, hidden worker model, autonomous scheduler or Actions model service is required.
The maw's own Git checkout/publication tools remain local. Recording this goal
starts no paid run, Actions dispatch, implementation, push, merge or release.

## Acceptance stages

### Mechanical stability without model spending

On the exact candidate, exercise a real hosted producer/transport and local inert
consumer with owned fixtures. Cover success, empty results, continuations, absent
rights, wrong refs, stale pending work, failed miners, malformed/expired/oversized
artifacts, uncertain/duplicate dispatch, cancellation and missing independent review.
Test local Windows/Linux consumers and supported Actions workers.

Use a fresh local profile and a transport/file-access audit to prove no forbidden
prey objects/tree/cache materialize. Do not delete historical developer caches to
make the test pass. Never run prey code/tests/builds/hooks; receiving tests are
explicitly scoped own-maw work on Actions.

### Owned complete-route proof

Before fresh discovery, an exposed/owned need must reach a local issue/PR dry-run
through the full route: an already-present/held lead, distinct useful continuation,
original receiving evidence, actual separate review when requested, legal clearance
and no local prey acquisition. This proves readiness, not fresh yield or superiority.

### Operational stability and effectiveness

Freeze the complete profile and sample before live calls. The reliability set has
at least ten preselected eligible end-to-end jobs across at least three owned maws,
including valid zero-finding cases. Require no unexplained lost state, unauthorized
effect, hidden retry, unqualified strict-budget certification or local prey acquisition.
Retain outages, interventions and failures; never replace disappointing cases silently.

Compare ordinary local Codex against the same model/effort plus the Actions-backed
Crab route, with equivalent receiving facts, source-access allowance and fixed caps.
Freeze treatment, order/exposure, original-claim identity, review completeness,
independent judgment and portfolio deduplication before inference. Equal limits
cannot conceal unequal source facts supplied to the two arms.

Provisional practical targets carried from earlier plans: **at least 80% confirmed
proposal precision**, at least equal pooled credited utility, **at least 25% greater
utility per investigation token**, and higher efficiency in at least two of three
maws. Empty denominators, incomplete reviews or unknown required usage remain
undecidable. A separately approved prospective protocol/budget must operationalize
these targets; this document is not a spending order or a universal statistical claim.

Report investigation and fully loaded cost separately, including local launch/final
responses, failed attempts, any model waiting, Actions queue/job/minutes/storage,
review and delivery. Cached input is not free; subscription counters are not API
invoices. If targets fail, leave the efficiency claim open rather than substituting
menu size, green CI or a retrospective shared review.

### Delivery and release

Demonstrate one real issue and one implemented/tested PR through the local delivery
boundary in owner-authorized maws. Reconcile actual provider state, review and
target policy. Publication is not human acceptance or default-branch retention;
record those later outcomes separately.

Regular exact-head tests, install, rights/security and version/tag/publication gates
remain required. The owner separately authorizes live runs and release. Marketplace
listing and scheduled autonomy are neither prerequisites nor automatic side effects.
