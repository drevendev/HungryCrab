## F1 — P1 — partial reconciliation loses legacy unknown costs

Corrected source: [usage reconciliation](https://github.com/drevendev/HungryCrab/blob/e1466b3cd8951e8f433ef5a3d0a2a0a4940436e2/src/hungry_crab/discovery_session.py#L471)
and [completeness projection](https://github.com/drevendev/HungryCrab/blob/e1466b3cd8951e8f433ef5a3d0a2a0a4940436e2/src/hungry_crab/discovery_session.py#L825).

The old schema stores an unknown usage receipt and `model_usage_complete=false`
without the newer `unresolved_usage` list. After a second unknown receipt is
reconciled, the previous code treats that newer list as complete and reports
the known subtotal as the entire actual model cost, although the original cost
is still unknown. The reproduced value was 11 where the actual total must be
unknown. This can misrepresent a historical investigation's cost.

Fix: derive outstanding operation usage from the original event history during
reconciliation and reporting. Allow exact legacy attributed recovery while
preserving genuinely unattributed unknown stops. Preserve all original events,
the terminal reason/time, exact receipt identity and once-only charging.

## F2 — P1 — unrelated receipts consume an admitted operation's terminal space

Corrected source: [durable byte reservation](https://github.com/drevendev/HungryCrab/blob/e1466b3cd8951e8f433ef5a3d0a2a0a4940436e2/src/hungry_crab/discovery_session.py#L261)
and [event reservation](https://github.com/drevendev/HungryCrab/blob/e1466b3cd8951e8f433ef5a3d0a2a0a4940436e2/src/hungry_crab/discovery_session.py#L273).

Admission checked the 500-event limit, but subsequent public accounting writes
could consume its reserved space. The native callback completed, then broker
settlement failed at the event limit before saving its actual usage. The same
problem prevented trusted completion of an older usage-only crash state.

Fix: each event append retains the remaining usage/terminal slots for every
admitted operation; each durable save also retains a bounded byte reserve.
Unrelated receipts refuse before consuming that capacity. Trusted exact
completion releases its own reservation. New work refuses before native begin
when its settlement cannot fit. Session event and byte limits remain unchanged.
